# Shadow Plan

Filled in by the `kt-handover` skill. Shadowing is how we prove the docs work.

- **Phase 1, <dates>: they shadow us** (about a month). First they watch us do each task. Then they do it while we watch.
- **Phase 2, <dates>: we shadow them.** They do each task. We watch and help only when they are stuck.

**Exit criteria:** every task is done by the new vendor alone in phase 2 with no help, or each remaining gap has a doc fix or an open question.

## Tasks

Type values: `daily`, `periodic`, `incident`, `known-issue`, `code-change`.
Status values: `todo`, `watched`, `done-with-help`, `done-alone`.

| Id | Task | Type | Document to follow | Phase 1 status | Phase 2 status | Help needed |
|---|---|---|---|---|---|---|

## Feedback

```
## S<number>: <date>, task <id>

- Done by: us | them, with us watching | them alone
- Document followed:
- Help needed: none | some | a lot, and what for
- Doc gaps: what was missing or wrong → fix in <document> | Q<n>
```
